# Read-only Changes panel

The user approved Changes after brainstorming and requested implementation, commit, push and Mac/iPhone updates. Continue the established Native workflow without further planning questions, on `codex/session-project-panel`; do not merge main or update iPad.

Add a permanent Changes tab beside Documents, Specs and Files. Show the repository name and branch, a filterable list grouped into Staged, Unstaged and Untracked, and selectable unified diffs with addition/deletion colours. Back returns to the list. Show explicit clean-repository, no-repository, binary, oversized and stale states. No stage, commit, revert, editor or terminal-input actions. Refresh on opening, manually, and every five seconds only while this tab and session are active; cancel/ignore stale results on navigation, app backgrounding or connection changes. Preserve terminal focus isolation and existing narrow full-panel presentation.

Use two fixed discovery operations `changes.list {}` and `changes.read {scope,file}` through existing exact pane/generation/gateway routing. Determine cwd from the actual pane and Git worktree from that cwd, supporting nested folders, unborn and detached branches and linked worktrees. Never use a client path or run a shell. Fixed Git argv disables pagers, prompts, fsmonitor, external diff and textconv; no fetch or network. List tracked modifications, additions, deletions, renames/conflicts and untracked files, without ignored files. Hash scope to route, cwd/root identities, HEAD/index state and file identities; revalidate before/after each read. Working-file symlink/unusual filename previews are explicitly unavailable; staged diffs read indexed data without following links. Cap listings at 500 displayed changes, Git stdout at 512 KiB, individual previews at 256 KiB and each command at four seconds. Label limits rather than silently truncate.

Approaches: a terminal `/diff` command would interfere with the prompt and depend on the agent; copying all diffs into catalog polling would add unnecessary work and memory. On-demand typed Git reads fit the existing host-local helper and keep discovery and input separate. The builder chooses unified selectable text, staged/unstaged entries for files changed in both, and status-based conflict labels.

Cover real temporary Git repositories (including spaces/literal pathspecs, deleted/binary/large files, renames, symlinks, cwd changes and worktrees), payload/routing validation, widget navigation/selection, refresh/background behaviour, read-only guarantees and light/dark narrow layouts. Run full Flutter/Python/Swift suites, one independent final review and release build 48; verify installed versions separately from launch results.
